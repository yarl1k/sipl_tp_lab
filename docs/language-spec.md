# Специфікація SIPL

## 1. Загальний опис

SIPL (SImple Programming Language) — проста мова з цілими числами та змінними.
Вона підтримує арифметичні вирази, умови, присвоювання, послідовне виконання,
розгалуження, цикли, блоки `begin/end` і `skip`. У мові немає оголошень змінних,
складних типів, процедур або операторів введення-виведення.

Специфікація спирається на БНФ та правила пріоритетів із практичної роботи 1
практикуму «Теорія програмування» (розділ «Синтаксис та семантика програм»).
Машинозчитуваний варіант цієї специфікації міститься в `grammar/sipl.ebnf`.

## 2. Синтаксичні категорії

| Категорія | Конструкції |
|---|---|
| `Prog` | `begin S end` |
| `Stm` | `x := a`, `S1 ; S2`, `if b then S1 else S2`, `while b do S`, `begin S end`, `skip` |
| `Aexp` | ціле число, змінна, `a1 + a2`, `a1 - a2`, `a1 * a2`, `(a)` |
| `Bexp` | `a1 = a2`, `a1 > a2`, `b1 ∨ b2`, `¬b`, `(b)` |
| `Var` | змінні `A`–`Z` |
| `Num` | цілі числа, зокрема від'ємні |

Реалізація використовує одну велику латинську літеру для імені змінної, як у
прикладах практикуму (`M`, `N`, `X`, `Y`, `R`). Це зафіксоване лексичне правило
цієї версії Toolkit.

Ключові слова пишуться малими літерами: `begin`, `end`, `if`, `then`, `else`,
`while`, `do`, `skip`. Булеві оператори використовують символи практикуму `∨`
та `¬`. Коментарі, десяткові числа й інші оператори не входять до базової SIPL.

## 3. Пріоритет та асоціативність

Для однозначного розбору використано пріоритети з практичної роботи 1
(від найвищого до найнижчого):

1. множення `*`;
2. додавання `+` та віднімання `-`;
3. порівняння `=` та `>`;
4. заперечення `¬`;
5. диз'юнкція `∨`;
6. присвоювання `:=`;
7. цикл `while ... do`;
8. умовний оператор `if ... then ... else ...`;
9. послідовне виконання `;`.

Бінарні операції є лівоасоціативними. Отже, `A - B - C` розбирається як
`(A - B) - C`, а `A + B * C` — як `A + (B * C)`.

Щоб уникнути неоднозначності оригінальної БНФ, рівні операторів уточнено в
`grammar/sipl.ebnf`. Послідовність має найнижчий пріоритет, тому тіло `while`
або гілку `if`, яка містить кілька операторів, потрібно групувати через
`begin ... end`. Вкладені `if` у гілках також можна однозначно записувати через
блок.

## 4. Лексичні правила

- Пробільні символи ігноруються між токенами.
- Числа складаються з десяткових цифр; знак мінус є частиною від'ємного
  числового літерала лише в позиції, де очікується первинний арифметичний вираз.
- Змінні — одна велика ASCII-літера `A`–`Z`.
- `:=` — єдиний оператор присвоювання.
- Дужки `(` та `)` групують арифметичні вирази або умови.
- Розрізняються регістри ключових слів і змінних.

## 5. Семантика виконання

Стан програми — скінченне відображення імен змінних у цілі значення
(`State = Var → Int`). Читання змінної, якої немає у стані, є невизначеною
операцією; інтерпретатор повідомляє `UndefinedVariableError`, а не підставляє
довільне значення.

- `X := a` обчислює `a` у поточному стані та оновлює значення `X`.
- `S1 ; S2` спочатку виконує `S1`, а потім `S2` на отриманому стані.
- `if b then S1 else S2` виконує одну гілку залежно від значення `b`.
- `while b do S` повторює `S`, доки `b` істинна, і завершується, коли вона хибна.
- `begin S end` групує оператори й не змінює їхньої семантики.
- `skip` не змінює стан.

Операції `+`, `-`, `*`, `=`, `>`, `∨`, `¬` мають звичайне математичне
значення. Для диз'юнкції обчислюються обидві предикатні функції: це відповідає
композиції суперпозиції з практичної роботи та правилу частковості функцій.

Початковий стан задається інструментами запуску, оскільки SIPL не має
операторів введення. Наприклад, `sipl run examples/power.sipl --set X=5 --set Y=2`.

## 6. Обмеження виконання

Інтерпретатор за замовчуванням обмежує кількість виконаних вузлів-операторів
100 000 кроками. Ліміт можна змінити через `--max-steps`. Перевищення ліміту
повідомляється як `StepLimitExceeded`. Це захищає CLI та тести від нескінченних
циклів; сама теоретична семантика не гарантує завершення кожної програми.
